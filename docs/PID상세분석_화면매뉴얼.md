# 로직 PID Analytics — PID 상세 분석 화면 사용 매뉴얼

| 항목 | 내용 |
|---|---|
| 화면명 | PID 상세 분석 (로직 PID Analytics v4) |
| 접속 경로 | `/pid/searchPIDTotal` |
| 대상 데이터 | `variant_h` (PID 헤더) · `variant_d` (PID 상세) |
| 문서 버전 | 1.0 (2026-09-05) |
| 작성 | 수배로직설계팀 |

---

## 1. 개요

PID 로직 데이터를 SPEC · CON · KEY · VAL · REMARKS 조건으로 조회하는 화면입니다.
기존 v3 화면의 조회 기능을 유지하면서 다음 항목을 보강했습니다.

- 조건 입력 전 **검색식 미리보기** 제공
- 결과 그리드의 **정렬 · 결과 내 검색 · 빈 컬럼 숨김 · 페이징**
- **최초 등록 조회** — 특정 문구가 최초로 등록된 PID · 버전 · 행 · 등록일 · 로직수정자 확인
- 조회 결과의 **CSV / 클립보드 / EXCEL** 반출

---

## 2. 화면 구성

| 영역 | 설명 |
|---|---|
| 상단 바 | 사이드바 토글, 다크/라이트 모드 전환 (브라우저에 상태 저장) |
| 도움말 | 검색 조건 요약. 기본 접힘 |
| 최초 등록 조회 | 문구의 최초 등록 시점 추적. 기본 접힘 |
| 검색 조건 | 조건 01 · 조건 02 · PID GROUP + 검색식 미리보기 |
| 검색 결과 | 그리드, 반출 버튼, 페이징 |

---

## 3. 검색 조건

### 3.1 조건 01 (필수)

| 항목 | 선택값 |
|---|---|
| 대상 필드 | `SPEC` 사양 · `CON` 조건 · `KEY` 키 · `VAL` 값 · `REMARKS` 비고 |
| 연산자 | `LIKE` 포함 · `EQUAL` 일치 |
| 값 | **필수 입력** |

값이 비어 있으면 조회되지 않습니다.

### 3.2 조건 02 (선택)

| 항목 | 선택값 |
|---|---|
| 대상 필드 | `SPEC` · `CON` · `KEY` · `VAL` (REMARKS 없음) |
| 연산자 | `LIKE` · `NOT LIKE` · `EQUAL` · `NOT EQUAL` |
| 값 | 비워두면 **조건 02 는 적용되지 않습니다** |

**제약** — 조건 01 의 대상 필드를 `REMARKS` 로 선택하면 조건 02 입력이 자동으로 잠깁니다.
서버 쿼리가 REMARKS 와 상세 컬럼을 동시에 결합하지 못하는 구조이며, 잠긴 상태에서 조회하면 입력값은 무시됩니다.

### 3.3 조건 결합 방식

조건 01 과 조건 02 사이의 선택 버튼입니다.

| 값 | 동작 |
|---|---|
| **단독** | 조건 01 · 02 가 **같은 번호**에서 함께 만족하는 행만 조회 (예: `SPEC1` ↔ `VAL1`) |
| **AND** | 조건 01 · 02 를 각각 만족 (번호가 달라도 됨) |

같은 항목쌍을 찾을 때는 **단독**, 한 행 안에 두 값이 어디든 있으면 되는 경우는 **AND** 를 사용합니다.

### 3.4 PID GROUP (선택)

PID 명칭 자체를 단계로 좁히는 조건입니다.

- 연산자 : `LIKE` · `NOT LIKE` · `EQUAL` · `NOT EQUAL`
- 입력 단계 : `PID-03` → `PID-04` → `PID-05` (앞 단계를 입력해야 다음 단계가 열립니다)
- **결합 규칙**
  - `LIKE` · `EQUAL` → 입력한 단계를 **OR** 로 묶음
  - `NOT LIKE` · `NOT EQUAL` → **AND** 로 묶음
- 전부 비워두면 PID GROUP 조건은 적용되지 않습니다.

앞 단계를 지우면 뒤 단계는 자동으로 잠기고 값도 비워집니다. `PID-04` 만 입력하거나 `PID-03` · `PID-05` 만 입력하는 조합은 사용할 수 없습니다.

### 3.5 검색식 미리보기

조건 카드 상단에 현재 조건이 논리식으로 표시됩니다. 조회 전 조건 결합이 의도대로 구성됐는지 확인하는 용도입니다.

```
SPEC LIKE "DOOR"  AND  VAL EQUAL "3.0"
( SPEC LIKE "DOOR" ) AND ( PID LIKE "A01" OR PID LIKE "A02" )
```

### 3.6 보조 기능

| 기능 | 설명 |
|---|---|
| 최근 검색 | 직전 조건 최대 **8건**을 불러옵니다. 브라우저(localStorage)에만 저장되며 PC·브라우저가 바뀌면 조회되지 않습니다 |
| 초기화 | 모든 조건을 기본값으로 되돌립니다 |
| 지우기 | 카드 단위로 해당 조건만 초기화합니다 |
| Enter 키 | 조건 입력창에서 Enter 를 누르면 즉시 검색합니다 |

## 4. 검색 결과

### 4.1 컬럼 체계

고정 4개 + 반복 컬럼으로 **총 104개** 컬럼입니다.

| 구분 | 컬럼 |
|---|---|
| 고정 | `PID` · `NO` · `ADDR` · `REMARKS` |
| 사양/조건 | `SPEC1~SPEC30` · `CON1~CON30` |
| 키/값 | `KEY1~KEY20` · `VAL1~VAL20` |

### 4.2 그리드 조작

| 기능 | 동작 |
|---|---|
| 정렬 | 헤더 클릭 시 오름차순, 재클릭 시 내림차순 (숫자 인식 정렬) |
| 결과 내 검색 | 조회된 데이터 안에서 다시 필터링합니다. 서버를 재호출하지 않습니다 |
| 빈 컬럼 숨기기 | 값이 전부 비어 있거나 `-` 인 컬럼을 숨깁니다. 고정 4개 컬럼은 항상 표시 (기본 켜짐) |
| 행 보기 | 25 / 50 / 100 / 200행 (기본 50행) |
| 행 툴팁 | 행에 마우스를 올리면 그 행의 `KEY → VAL` 쌍이 요약 표시됩니다 |
| 셀 더블클릭 | 해당 값과 그 행의 PID 로 **최초 등록 조회**를 실행합니다 (VAL 대상) |

결과 건수와 조회 소요 시간은 결과 카드 헤더에 표시됩니다.

## 5. 데이터 반출

| 버튼 | 대상 | 비고 |
|---|---|---|
| **Copy** | 현재 **결과 내 검색이 적용된 전체 행** · 전체 104컬럼 | 탭 구분(TSV). 엑셀에 바로 붙여넣기 |
| **CSV** | 동일 | UTF-8 BOM 포함, 파일명 `csv_Result.csv` |
| **EXCEL Download** | **서버에서 조건으로 재조회**한 결과 | 대용량 조회 시 사용 |

**권장 사용**

- 조회 결과가 **10,000건 이상**이면 EXCEL Download 를 사용하십시오.
- 현재 EXCEL 다운로드 파일에 **숫자 인식 관련 이슈**가 있습니다. 수치 데이터를 다루는 경우 Copy 후 엑셀에 붙여넣는 방식을 권장합니다.
- Copy · CSV 는 화면에 조회된 데이터를 기준으로 하므로, 결과 내 검색을 걸어둔 상태라면 **필터된 행만** 반출됩니다.

## 6. 최초 등록 조회

특정 문구가 **언제 · 누구에 의해 · 어느 버전에서 처음 등록되었는지** 추적하는 기능입니다.
화면 상단의 접이식 패널에서 사용합니다.

### 6.1 입력

| 항목 | 필수 | 설명 |
|---|---|---|
| PID 입력 | 필수 | 조회 대상 PID 명칭 |
| 찾고자하는 문구 | 필수 | 부분 일치로 검색합니다 |

두 항목 모두 입력해야 조회됩니다.

### 6.2 조회 버튼

| 버튼 | 검색 대상 컬럼 |
|---|---|
| **조회** | `VAL1 ~ VAL20` |
| **전체컬럼대상조회** | `SPEC1~30` · `CON1~30` · `KEY1~20` · `VAL1~20` |

문구가 VAL 이 아닌 SPEC · CON · KEY 에 들어 있을 가능성이 있으면 전체컬럼대상조회를 사용합니다. 대상 컬럼이 넓어지는 만큼 응답 시간은 더 소요됩니다.

### 6.3 판정 기준

- 기준일 **2025-01-01 이전** 등록분에서 먼저 찾고, 결과가 없을 때만 그 이후 등록분에서 다시 찾습니다.
- 등록일(`REG_DATE`) → 버전(`VERSION`) 오름차순으로 정렬해 **가장 먼저 등록된 버전 1건**만 반환합니다.
- 임시 버전(`VERSION = -1`)은 대상에서 제외됩니다.
- 같은 버전에서 여러 행이 걸리면 해당 행들이 모두 반환됩니다.

### 6.4 결과 확인

팝업 상단에 **PID · 버전 · 행(NO) · 등록일 · 로직수정자** 5개 항목이 표시되고, 아래에 검색 문구 · 검색 대상 컬럼 · PID 조건 · PID 명 · REMARKS 가 이어집니다.

같은 버전에서 여러 행이 걸린 경우 **같은 버전에서 걸린 행** 표가 추가로 표시됩니다. (행 NO 오름차순, 화면에는 최대 200행)

**결과 복사** 버튼으로 표 전체를 엑셀 붙여넣기용 형식(TSV)으로 복사할 수 있습니다.

> **로직수정자** 는 해당 버전을 등록·수정한 담당자 이름입니다. 사용자 정보가 남아 있지 않은 과거 데이터는 `—` 로 표시됩니다.

## 7. 제약 사항 및 참고

1. 조건 01 을 `REMARKS` 로 선택하면 조건 02 를 사용할 수 없습니다.
2. 조건 02 의 값이 비어 있으면 해당 조건은 적용되지 않은 채 조회됩니다.
3. PID GROUP 은 `PID-03` 부터 순서대로 입력해야 하며 중간 단계를 건너뛸 수 없습니다.
4. 최근 검색 · 다크모드 설정은 **사용 중인 브라우저에만** 저장됩니다. PC 를 옮기면 초기화됩니다.
5. 최초 등록 조회는 PID 와 문구가 **모두** 입력되어야 동작합니다.
6. 결과 그리드의 셀 더블클릭 및 입력창 Enter 는 **VAL 대상** 최초 등록 조회로 동작합니다. 전체 컬럼 조회는 버튼으로만 실행됩니다.
7. EXCEL 다운로드 파일의 숫자 인식 이슈는 확인된 사항이며 개선 예정입니다. 그 전까지는 Copy 사용을 권장합니다.

## 8. 활용 예시

**특정 사양이 적용된 로직 확인**
조건 01 : `SPEC` / `LIKE` / `DOOR` → 검색 → 결과 내 검색으로 추가 범위 축소

**사양과 값이 짝을 이루는 행만 확인**
조건 01 : `SPEC` / `LIKE` / `DOOR`, 조건 02 : `VAL` / `EQUAL` / `3.0`, 결합 방식 **단독**

**특정 PID 계열만 대상으로 조회**
조건 01 입력 후 PID GROUP 연산자 `LIKE`, `PID-03` 에 상위 코드 입력 → 하위 단계 순차 입력

**문구가 언제부터 쓰였는지 확인**
최초 등록 조회에 PID 와 문구를 입력 → `조회`(VAL 대상) → 결과가 없으면 `전체컬럼대상조회`

## 부록. 연동 API

화면이 호출하는 서버 엔드포인트입니다. 장애 문의 시 참고용입니다.

| 기능 | 메서드 · 경로 |
|---|---|
| PID 상세 검색 | `POST /pid/searchPIDSpecViewJson` |
| EXCEL 다운로드 | `POST /excel/searchPIDExcel` |
| PID 전체 버전 조회 | `GET /pid/findPIDList` |
| 최초 등록 조회 (VAL) | `POST /pid/findFirstPID` |
| 최초 등록 조회 (전체 컬럼) | `POST /pid/findFirstPIDAsALLColumn` |
