# PID 플레이그라운드 — 화면 사용 매뉴얼

| 항목 | 내용 |
|---|---|
| 화면명 | PID 플레이그라운드 |
| 접속 경로 | `/simulplay/pidSimulPlayGround` |
| 대상 데이터 | PID 로직(DB) · 공사(호기) 영업사양 |
| 저장 여부 | **DB 미저장** — 수정한 로직은 이 화면에서 실행할 때만 사용됩니다 |
| 문서 버전 | 1.0 (2026-10-12) |
| 작성 | 수배로직설계팀 |

---

## 1. 개요

PID 로직을 불러와 **엑셀처럼 표에서 직접 고친 뒤, DB 에 저장하지 않고 바로 실행**해 보는 화면입니다.

- SPEC / CON / KEY / VAL / GOTO 를 고치거나 라인을 추가 · 복제 · 삭제한 뒤
- 공사번호(호기)를 넣고 실행하면 라인마다 **TRUE / FALSE / 미실행** 과 **그 시점의 값**이 표시되고
- **디버거처럼 한 단계씩** 앞뒤로 이동하며 변수(resultMap)가 어떻게 바뀌는지 따라갈 수 있습니다.
- 고친 내용은 **변경 내역** 탭에서 `DB 원본 → 수정` 형태로 정리되어, PLM 에 옮겨 적을 때 참고할 수 있습니다.

> PID 실행 시뮬레이터(`/pid/pidSimulView`)가 **"지금 DB 로직이 왜 이런 결과를 냈는가"** 를 보는 화면이라면,
> 플레이그라운드는 **"이렇게 고치면 결과가 어떻게 바뀌는가"** 를 DB 를 건드리지 않고 미리 확인하는 화면입니다.

---

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────────────────────┐
│ 헤더  : ① PID 불러오기 → ② 실행 대상 → ▶ 실행 · 실시간 실행 · PID 정보  │
├──────────────────────────────────────────────────────────────────────┤
│ 편집 도구 : 수정 현황 · SPEC/KEY 열 · 확대 · 되돌리기                     │
├──────────────────────────────────────────────────────────────────────┤
│ 편집 표 (PID 로직) — 실행 결과 색 · 단계 · OUTPUT 함께 표시             │
├────────────────────── (끌어서 높이 조절) ────────────────────────────┤
│ 디버그 패널 : 실행 요약 · 단계 이동 · 탭(라인별 결과 / 라인 상세 / 변수 …) │
└──────────────────────────────────────────────────────────────────────┘
```

| 영역 | 설명 |
|---|---|
| 헤더 | PID · 버전 선택 → 불러오기, 공사번호 입력 → 실행 |
| 편집 도구 줄 | 수정 현황 표시와 편집 보조 기능 |
| 편집 표 | 불러온 PID 로직. 직접 수정 가능 |
| 디버그 패널 | 실행 결과를 여러 관점(탭)으로 확인. 경계선을 끌어 높이 조절, `접기` 로 머리줄만 남기기 |

---

## 3. 기본 사용 순서

1. **PID 불러오기** — `PID` 입력, `버전` 선택(기본 최신) 후 **불러오기**
2. **수정** — 편집 표에서 SPEC / CON / KEY / VAL 등을 고침 (수정 안 하고 바로 실행해도 됨)
3. **실행** — `공사번호` 입력 후 **실행** 또는 <kbd>Ctrl</kbd>+<kbd>Enter</kbd>
4. **확인** — 편집 표 색과 하단 디버그 패널에서 결과 확인, 단계 이동(<kbd>F10</kbd>)으로 추적
5. **(선택) 반영** — `변경 내역` 탭에서 수정 내용을 확인해 PLM 에서 실제 반영

## 4. 헤더

### 4.1 ① PID 불러오기

| 항목 | 필수 | 설명 |
|---|---|---|
| PID | 필수 | 예: `D375A`. 입력하면 버전 목록이 자동으로 갱신됩니다 |
| 버전 | 선택 | `최신`(기본) · `TEST` · `vN · 등록일` 중 선택 |
| 불러오기 | | DB 에서 로직을 읽어 편집 표에 표시. 완료되면 ① 번호가 초록색으로 바뀝니다 |

불러오면 헤더 오른쪽에 PID 정보가 표시됩니다.

```
D375A  PID명  [v12 (최신)] [2026-10-01] [층별 PID] · 128라인
```

- **층별 PID** 태그가 있으면 `추가 조건 → 층(FLOOR_NAME)` 을 입력할 수 있습니다.
- **JAVA** 태그가 있는 PID 는 라인이 없어 편집할 수 없고, 실행하면 DB 원본(JAVA) 실행 결과만 보여줍니다.

### 4.2 ② 실행 대상

| 항목 | 필수 | 설명 |
|---|---|---|
| 공사번호 | 필수 | 공사번호(예: `206663L01`) 또는 공사정보 ouid (예: `elv_info$vf@a810066d`) |
| 추가 조건 ▾ | 선택 | 아래 항목을 펼칩니다 |
| └ 층 (FLOOR_NAME) | 선택 | **층별 PID 일 때만** 입력 가능 |
| └ 전처리 PID | 선택 | 실행 전에 먼저 돌릴 PID. 쉼표로 여러 개 (예: `EL_P001, EL_P002`) |

> CALL 로 호출되는 **하위 PID 와 전처리 PID 는 항상 최신 버전(DB 원본)** 으로 실행됩니다.
> 수정본은 **불러온 PID 에만** 적용됩니다.

### 4.3 실행 / 실시간 실행

| 기능 | 설명 |
|---|---|
| ▶ 실행 | 지금 편집 표의 내용(수정본)으로 실행. PID 를 불러온 뒤에만 활성화 |
| 실시간 실행 (스위치) | 켜 두면 표를 고칠 때마다 **0.8초 뒤 자동으로 다시 실행**. 기본 켜짐, 설정은 브라우저에 기억 |

- 셀을 편집하는 도중(입력 중)에는 실시간 실행이 입력을 방해하지 않도록 기다립니다.
- PID 입력칸 값이 불러온 PID 와 다르면 실행 전에 확인 창이 뜹니다. (실행은 **불러온 PID** 기준)

### 4.4 주소로 바로 열기 · 공유

불러오기 · 실행하면 주소창에 조건이 반영됩니다. 주소를 공유하면 열자마자 같은 PID 를 불러와 실행합니다.

```
/simulplay/pidSimulPlayGround?pid=D375A&version=12&project=206663L01
```

> 주소에는 **수정 내용이 포함되지 않습니다.** 받은 사람은 DB 원본으로 시작합니다.

## 5. 편집 표

### 5.1 컬럼

| 컬럼 | 편집 | 설명 |
|---|---|---|
| 단계·결과 | - | `단계번호. TRUE/FALSE`, 미실행은 `-` |
| NO | - | DB 라인 번호 (새로 추가한 라인은 비어 있음) |
| ADDR | O | 라인 주소 |
| SPEC*n* / CON*n* | O | 조건. 기본 3쌍, 최대 30쌍 |
| KEY*n* / VAL*n* | O | 결과. 기본 2쌍, 최대 20쌍 |
| GOTO | O | 이동할 ADDR |
| REMARKS | O | 비고 |
| OUTPUT (실행 결과) | - | 그 라인에서 계산된 출력 |

`단계·결과`, `NO`, `ADDR` 은 왼쪽에 고정되어 가로 스크롤해도 보입니다.

### 5.2 편집 방법

| 동작 | 방법 |
|---|---|
| 값 수정 | 셀 더블클릭 또는 바로 입력. 엑셀에서 복사 · 붙여넣기 가능 |
| 라인 추가 | 오른쪽 클릭 → `위에 라인 추가` / `아래에 라인 추가`, 또는 맨 아래 빈 줄에 입력 |
| 라인 복제 | 오른쪽 클릭 → `라인 복제 (아래에)` |
| 라인 삭제 | 오른쪽 클릭 → `라인 삭제` |
| 순서 변경 | 왼쪽 행 번호를 끌어서 이동 |
| 되돌리기 | <kbd>Ctrl</kbd>+<kbd>Z</kbd> / 다시 실행 <kbd>Ctrl</kbd>+<kbd>Y</kbd> |
| 열 추가 | 편집 도구 줄 `+ SPEC 열` / `+ KEY 열` |
| 열 너비 | 헤더 경계를 끌어서 조절 |

> 빈 칸은 DB 의 NULL 과 같게 취급합니다.

### 5.3 색 · 표시 (범례)

| 표시 | 의미 |
|---|---|
| 초록 행 | TRUE — 조건을 만족해 실행된 라인 |
| 빨강 행 | FALSE — 조건 불만족 |
| 회색 행 | 미실행 — GOTO / STOP 으로 건너뜀 |
| 진한 초록 칸 + `✓` | 해당 SPEC 조건 일치 |
| 진한 빨강 칸 + `✗` | 해당 SPEC 조건 불일치 |
| 왼쪽 주황 줄 + 굵은 글씨 | 수정한 칸 — 마우스를 올리면 **DB 원본 값** 표시 |
| 하늘색 테두리 | 새로 추가한 라인 |
| 보라색 위아래 줄 | 디버거 **현재 단계** 라인 |
| 흐린 표시 | 실행 후 또 수정함 → 결과가 최신이 아님 |

조건 칸에 마우스를 올리면 비교 내용을 보여줍니다.

```
SPEC2 불일치
EL_SPEED 값 : 105
CON : {EL_X} → 90
```

## 6. 편집 도구 줄

### 6.1 수정 현황

| 표시 | 의미 |
|---|---|
| `DB 원본과 같음` | 수정 없음 |
| `수정 N칸 (M라인)` | 값이 바뀐 칸 / 라인 수 |
| `추가 N라인` · `삭제 N라인` · `순서 변경` | 라인 단위 변경 |

### 6.2 버튼

| 버튼 | 설명 |
|---|---|
| + SPEC 열 / + KEY 열 | 조건 · 결과 열 한 쌍 추가 |
| − 100% + | 편집 표 확대/축소 (표 위에서 <kbd>Ctrl</kbd>+휠도 가능). `100%` 클릭 시 원래대로 |
| DB 원본으로 되돌리기 | 모든 수정을 버리고 DB 원본을 다시 불러옴 |
| 범례 / 단축키 | 색 의미와 단축키 안내 |

### 6.3 수정 내용 보관

- 수정 내용은 **어디에도 저장되지 않습니다.** 새로고침하거나 다른 PID 를 불러오면 사라집니다.
- 수정한 내용이 있으면 다른 PID 를 불러오거나 페이지를 떠날 때 확인 창이 뜹니다.
- 남겨 두려면 편집 표에서 셀을 선택해 <kbd>Ctrl</kbd>+<kbd>C</kbd> 로 복사한 뒤 엑셀에 붙여넣어 보관하세요. 다시 쓸 때는 PID 를 불러온 뒤 편집 표에 붙여넣으면 됩니다.

## 7. 디버그 패널

### 7.1 상단 요약 · 단계 이동

```
TRUE 42  FALSE 51  미실행 35   206663L01 · 1.8초   [최신 결과]        |◀  ◀  단계 7 / 42 · A120 TRUE  ▶  ▶|   − 100% +   [▾ 접기]
```

| 항목 | 설명 |
|---|---|
| TRUE / FALSE / 미실행 | 라인 결과 건수 |
| `최신 결과` / `수정 후 미실행` | 실행 후 또 고쳤으면 `수정 후 미실행` 으로 바뀜 → 다시 실행 필요 |
| 단계 이동 | 처음 · 이전(<kbd>Shift</kbd>+<kbd>F10</kbd>) · 다음(<kbd>F10</kbd>) · 마지막 |
| − 100% + | 디버그 패널 표 확대/축소 (패널 위 <kbd>Ctrl</kbd>+휠, 또는 <kbd>+</kbd> <kbd>-</kbd> <kbd>0</kbd>) |
| ▾ 접기 / ▴ 펼치기 | 탭 · 결과 영역을 접어 **편집 표를 넓게** 봅니다. 접어도 이 머리줄(실행 요약 · 단계 이동)은 남아 <kbd>F10</kbd> 으로 계속 따라갈 수 있습니다. 접힘 상태는 브라우저에 기억 |

**단계** 는 실제로 실행된(TRUE · FALSE) 라인의 실행 순서입니다. 단계를 옮기면 **편집 표 · 라인별 결과 · 라인 상세 · 변수** 가 모두 그 라인을 따라갑니다.
편집 표에서 실행된 라인을 클릭해도 그 단계로 이동합니다.

### 7.2 탭

| 탭 | 내용 |
|---|---|
| 라인별 결과 | 전체 라인의 실행 결과 표 (아래 7.3) |
| 라인 상세 | 선택한 라인의 조건 비교 · 바뀐 값 · OUTPUT (아래 7.4) |
| 변수 | **현재 단계까지** 실행했을 때의 resultMap (아래 7.5) |
| 최종 OUTPUT | 실행이 끝난 뒤의 최종 resultMap. 키 / 값 검색 |
| 최종 영업사양 | PID 실행 후의 영업사양(특성코드 = 값). 검색 가능 |
| 하위 PID | CALL 로 실행된 하위 PID 목록 — 이름 · 실행 버전 · 호출 횟수 · 깊이 · 오류 |
| 변경 내역 | DB 원본 대비 수정 내용 (아래 7.6) |

### 7.3 라인별 결과

| 컬럼 | 설명 |
|---|---|
| 단계 | 실행 순서 |
| # / NO / ADDR | 편집 표 행 번호 / DB 라인 번호(새 라인은 `새`) / 주소 |
| 결과 | TRUE · FALSE · `-` |
| 조건 (SPEC = CON [그 시점 값]) | 예: `✗ EL_SPEED = 90 [105]` — 대괄호는 **그 라인을 실행하던 시점의 실제 값** |
| 결과 (KEY = VAL) | 라인에 정의된 결과 |
| 바뀐 값 | 이 라인 실행으로 바뀐 변수 `KEY 이전 → 이후` (최대 6개, 나머지는 `+N개`) |
| GOTO / REMARK | |

- **필터** : `전체` · `실행된 라인` · `TRUE` · `FALSE` · `미실행`
- **값이 바뀐 라인만** : 실제로 값을 바꾼 라인만 표시
- **검색** : SPEC / KEY / VAL / 값 / ADDR / REMARK 등 키워드 검색
- 행 **클릭** → 그 단계로 이동, **더블클릭** → 라인 상세 탭

### 7.4 라인 상세

| 영역 | 내용 |
|---|---|
| 머리 | 결과 배지 · 단계 · NO · ADDR · GOTO · REMARK |
| 조건 | `SPEC` · `그 시점 값` · `CON` · `CON 계산값` · `일치/불일치` (CON 이 비어 있으면 항상 일치) |
| 이 라인으로 바뀐 값 | KEY · 이전 · 이후 |
| OUTPUT | 이 라인의 출력 |
| CALL 실행 후 resultMap | CALL 라인일 때 하위 PID 실행 직후의 resultMap (검색 가능, 라인 KEY 는 노란색 강조) |

### 7.5 변수 (감시)

- 현재 단계까지의 변경을 차례로 적용한 resultMap 을 보여줍니다.
- **노란색** = 이 단계에서 바뀐 값. `마지막 변경` 의 `단계 N` 을 누르면 그 단계로 이동합니다.
- **감시할 키** 에 `EL_A, EL_B` 처럼 입력하면 그 키가 항상 맨 위에 고정됩니다. (아직 값이 없어도 표시, 브라우저에 기억)
- <kbd>F10</kbd> 으로 한 단계씩 넘기며 감시 키 값의 변화를 따라가는 것이 기본 사용법입니다.

### 7.6 변경 내역

PLM 에 옮겨 적기 쉽도록 수정 내용을 정리합니다.

| 라인 | 칸 | DB 원본 | 수정 |
|---|---|---|---|
| 5번째 줄 (NO 5) · A050 | CON2 | 90 | 105 |
| 12번째 줄 | `추가` | | ADDR=A125, SPEC1=EL_TYPE, … |
| NO 30 · A300 | `삭제` | SPEC1=…, KEY1=… | |

라인 순서가 바뀌었으면 상단에 `라인 순서가 DB 원본과 다릅니다.` 가 표시됩니다.

## 9. 활용 예

### 9.1 조건 하나를 바꾸면 결과가 어떻게 달라지나?

1. PID 불러오기 → 공사번호 입력 → 실행 (실시간 실행 켜 둠)
2. 바꾸고 싶은 CON 셀을 수정 → 0.8초 뒤 자동 재실행
3. `최종 OUTPUT` 탭에서 결과값 비교, 편집 표에서 TRUE/FALSE 가 바뀐 라인 확인

### 9.2 특정 변수가 어디서 잘못 들어가는지 추적

1. `변수` 탭 → 감시할 키에 해당 변수 입력
2. 단계 `|◀` 처음으로 → <kbd>F10</kbd> 으로 한 단계씩 진행
3. 노란색으로 바뀌는 단계에서 멈추고 `라인 상세` 로 조건 · 값 확인

### 9.3 수정안 정리 후 PLM 반영

1. 수정 · 검증 완료 후 `변경 내역` 탭을 캡처하거나, 편집 표를 복사(<kbd>Ctrl</kbd>+<kbd>C</kbd>)해 엑셀로 정리
2. PLM 에서 실제 PID 수정 · 등록

## 10. 주의사항 · FAQ

| 상황 | 설명 |
|---|---|
| 고친 내용이 DB 에 반영되나요? | **아니요.** 실행할 때만 사용됩니다. 실제 반영은 PLM 에서 해야 합니다 |
| 새로고침했더니 수정이 사라졌어요 | 수정 내용은 저장되지 않습니다. 남기려면 편집 표를 복사(<kbd>Ctrl</kbd>+<kbd>C</kbd>)해 엑셀에 보관하세요 |
| 나중에 / 다른 PC 에서 이어서 하고 싶어요 | 엑셀에 보관한 내용을 PID 를 불러온 뒤 편집 표에 붙여넣으세요 |
| 하위 PID 를 고쳐서 실행하고 싶어요 | CALL 하위 PID 는 항상 최신 DB 버전으로 실행됩니다. 하위 PID 자체를 불러와 따로 실행하세요 |
| `층` 입력칸이 비활성이에요 | 층별 PID 가 아닌 경우입니다 |
| JAVA PID 는 편집이 안 돼요 | JAVA 방식은 라인이 없어 편집할 수 없고, 실행 결과(resultMap)만 볼 수 있습니다 |
| 상단에 주황/빨강 띠가 떠요 | 하위 PID 실행 실패 등 경고(주황) 또는 불러오기·실행 오류(빨강)입니다. 내용을 확인 후 `✕` 로 닫습니다 |
| `Handsontable 을 불러오지 못했습니다` | 편집 표 라이브러리를 `cdn.jsdelivr.net` 에서 받습니다. 사내망에서 해당 주소 접근이 막혔는지 확인하세요 |
| 결과가 흐리게 보여요 | 실행 후 수정한 상태입니다. 다시 실행하거나 실시간 실행을 켜세요 |
