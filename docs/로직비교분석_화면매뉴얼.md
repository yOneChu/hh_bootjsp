# 로직 비교 분석 화면 매뉴얼

같은 PID의 두 버전(과거 / 최신) 로직 데이터를 행·열 단위로 비교해서 달라진 부분을 찾아주는 화면이다.

| 항목 | 내용 |
|---|---|
| 접속 주소 | `/diff/logicViewUp` |
| 화면 파일 | `src/main/resources/templates/thymeleaf/logicViewDiffV3.html` |
| 화면 스크립트 | `src/main/resources/static/javascript/logicViewDiffV3.js` |
| 서버 컨트롤러 | `com.kyhslam.controller.LogicDiffControll` |
| 비교 로직 | `com.kyhslam.util.LogicDiffUtil` |
| 대상 테이블 | `variant_h`(버전 헤더), `variant_d`(로직 행) |

> 이 문서는 2026-11-16 개편본 기준이다. 개편본은 컴파일과 알고리즘 단위 확인까지만 했고,
> 실제 DB 데이터로 화면을 띄운 검증은 아직 하지 않았다. ([8. 미흡한 점](#8-미흡한-점--알려진-한계) 참고)

## 1. 화면 구성

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 제목 / 조회 조건   PID [    ] [버전 조회] | 과거 [▼] ⇄ 최신 [▼] [비교 실행] │
├──────────────────────────────────────────────────────────────────────┤
│ ② 도구 막대   +추가 n  ~수정 n  −삭제 n  =동일 n   ▲ 3/27 ▼  [검색]        │
│               □차이 있는 열만  ☑빈 열 숨기기   표시 n / 전체 n행   [CSV]     │
├───────────────────────────────────────────────┬──────────────────────┤
│ ③ 비교 표                                      │ ④ 상세 비교 패널       │
│  상태 | NO | ADDR | SPEC1 | CON1 | ... | REMARKS │  항목 | 과거 | 최신    │
│  (왼쪽 3열 고정)                                 │  (행을 클릭하면 열림)   │
├───────────────────────────────────────────────┴──────────────────────┤
│ ⑤ 범례                                                                │
└──────────────────────────────────────────────────────────────────────┘
```

② 도구 막대는 비교를 한 번 실행한 뒤에 나타난다.

## 2. 기본 사용 순서

1. **PID 입력** 후 `버전 조회` 버튼을 누르거나 Enter를 친다. 소문자로 입력해도 대문자로 바꿔서 조회한다.
2. **기준 버전(과거)** 과 **비교 버전(최신)** 을 각각 고른다.
   - 목록은 `v버전 | 등록일 | 이름 | 비고` 형식으로 나온다. 버전이 `-1`이면 `TEST`로 표시된다.
   - 가운데 `⇄` 버튼은 두 선택을 서로 바꾼다.
3. `비교 실행`을 누른다.
4. 결과 표에서 색칠된 행·셀을 확인한다. 행을 클릭하면 오른쪽에 상세 비교가 열린다.

입력이 빠졌거나 같은 버전을 양쪽에 고르면 화면 아래에 안내 문구가 뜨고 비교는 실행되지 않는다.

## 3. 결과 읽는 법

### 3.1 행 상태

| 표시 | 의미 | 행 배경 |
|---|---|---|
| `+ 추가` | 최신 버전에만 있는 행 | 연녹색 |
| `~ 수정` | 양쪽에 모두 있고 값이 달라진 행 | 연노랑 |
| `~ 열이동` | 값은 그대로인데 열 위치만 달라진 행 (수정으로 집계) | 연노랑 |
| `− 삭제` | 과거 버전에만 있는 행 (취소선) | 연빨강 |
| `= 동일` | 양쪽이 완전히 같은 행 | 흰색, 흐린 글씨 |

행은 최신 버전 순서대로 나오고, 삭제된 행은 과거 버전에서 있던 자리에 끼워서 보여준다.

상태 옆에 붙는 보조 태그:

| 태그 | 의미 |
|---|---|
| `순서` | 과거 버전과 비교해 다른 행들과의 상대 순서가 바뀐 행. 중간에 행이 추가·삭제돼서 번호만 밀린 경우에는 붙지 않는다. |
| `유사` | ADDR이 달라 ADDR로는 짝을 찾지 못했고, 내용이 비슷해서 같은 행으로 판단한 행. 엉뚱한 짝일 수 있으니 확인이 필요하다. |

### 3.2 NO / ADDR 열

- **NO**: 과거와 최신의 번호가 다르면 `3 → 4`처럼 둘 다 보여준다. NO는 비교 대상이 아니므로 번호만 달라진 것은 "수정"으로 잡히지 않는다.
- **ADDR**: 행을 식별하는 값. 폭이 150px로 고정이라 길면 말줄임(…) 처리되고, 전체 값은 상세 패널에서 볼 수 있다.

### 3.3 셀 차이 4종

"수정" 행 안에서 달라진 셀만 색이 칠해진다.

| 색 | 기호 | 의미 | 셀 표시 |
|---|---|---|---|
| 노랑 | (없음) | 값 변경 | 위에 최신 값(굵게), 아래에 과거 값(취소선). 달라진 글자 부분은 한 번 더 강조 |
| 녹색 | `+` | 값 추가 (과거에는 비어 있었음) | 최신 값 |
| 빨강 | `−` | 값 삭제 (최신에서는 비어 있음) | 과거 값(취소선) |
| 남보라 | `← SPEC2` | 열 위치만 이동 | 최신 값 + 과거에 있던 열 이름 |

`← SPEC2`는 "이 값은 과거 버전에서는 SPEC2 열에 있었다"는 뜻이다. 값 변경·값 삭제 셀에도 과거 위치가 다르면 같이 붙는다.

### 3.4 열 헤더

- 헤더 위쪽 색 띠로 열 묶음을 구분한다: 파랑 = 조건(SPEC/CON), 청록 = 결과(KEY/VAL), 보라 = 기타(GOTO, REMARKS).
- 헤더 옆 숫자 배지는 그 열에서 차이가 난 행 수다. (수정 행의 변경 셀 + 추가/삭제 행 중 값이 있는 셀)

## 4. 도구 막대 기능

| 기능 | 설명 |
|---|---|
| 상태 칩 (추가/수정/삭제/동일) | 건수를 보여주면서 필터 역할도 한다. 누르면 해당 상태의 행이 숨겨지고 점선 테두리로 바뀐다. 다시 누르면 보인다. |
| 부가 요약 | 칩 옆에 `변경 셀 n · 순서 변경 n행 · 열 이동만 n행 · 유사 매칭 n행`이 해당될 때만 표시된다. |
| 변경 이동 `▲ n/m ▼` | 화면에 보이는 변경 행(추가/수정/삭제)만 차례로 이동한다. 끝에 닿으면 처음으로 돌아간다. 첫 변경 셀이 화면 밖이면 가로로도 스크롤한다. |
| 검색 | ADDR이나 셀 값(과거·최신 모두)에 검색어가 들어 있는 행만 남긴다. 대소문자 구분 없음. |
| 차이 있는 열만 | 차이가 하나도 없는 열을 숨긴다. |
| 빈 열 숨기기 | 모든 행에서 값이 없는 열을 숨긴다. 기본으로 켜져 있고 끄면 82개 열이 모두 나온다. |
| 표시 n / 전체 n행 | 필터·검색 적용 후 보이는 행 수. |
| CSV | 지금 화면에 보이는 행과 열만 CSV로 저장한다. ([6. CSV 내보내기](#6-csv-내보내기)) |

필터와 검색 결과 보이는 행이 하나도 없으면 표 아래에 `필터 · 검색 초기화` 버튼이 나온다.

### 단축키

| 키 | 동작 |
|---|---|
| `N` | 다음 변경 행으로 이동 |
| `P` | 이전 변경 행으로 이동 |
| `Esc` | 상세 비교 패널 닫기 |
| `Enter` (PID 입력칸) | 버전 조회 |
| `Ctrl` + 클릭 | 행 강조를 추가/해제 (여러 행을 동시에 표시해 둘 때) |

`N` / `P`는 입력칸이나 선택 상자에 커서가 있을 때는 동작하지 않는다.

## 5. 상세 비교 패널

행을 클릭하면 오른쪽에 열린다. 표에서는 옆으로 길게 늘어진 한 행을 **항목 / 과거 / 최신** 세로 표로 다시 보여준다.

- 상단: 상태, ADDR, `NO 과거 → 최신`, 변경 셀 수, 행 순서 변경·유사 매칭 여부
- 본문: 값이 있는 항목만 나열하고, 차이가 있는 항목에는 `값 변경 / 값 추가 / 값 삭제 / 열 위치 이동` 구분이 붙는다.
- `차이 있는 항목만`을 켜면 달라진 항목만 남는다.
- 닫기: 오른쪽 위 `×` 버튼 또는 `Esc`.

화면 폭이 1100px 이하이면 패널이 표 아래쪽으로 내려간다.

## 6. CSV 내보내기

- 대상: 현재 필터·검색·열 숨김이 적용된 상태 그대로.
- 파일명: `로직비교_{PID}.csv` (엑셀에서 한글이 깨지지 않도록 UTF-8 BOM 포함)
- 열 구성: `상태, NO(과거), NO(최신), 비고, ADDR, (보이는 열들)`
- 비고 열에는 `열이동 / 순서변경 / 유사매칭`이 들어간다.
- 변경된 셀은 `최신값  [이전: 과거값]` 형식으로 한 칸에 들어간다.
- 삭제 행은 과거 값이 들어간다.

## 7. 비교 방식 (동작 원리)

### 7.1 행 매칭 — 3단계

몇 번째 행인지(위치)로 비교하지 않고, 아래 순서로 과거 행과 최신 행의 짝을 찾는다.

| 단계 | 기준 | 결과 |
|---|---|---|
| 1 | 모든 열(ADDR 포함)의 값이 완전히 같은 행 | 동일 |
| 2 | 남은 행 중 ADDR이 같은 행 | 셀 단위로 비교 → 수정 |
| 3 | 남은 행 중 내용이 60% 이상 비슷한 행 | 수정 + `유사` 태그 |

끝까지 짝이 없는 최신 행은 **추가**, 짝이 없는 과거 행은 **삭제**가 된다.

그래서 중간에 행 하나가 새로 들어가도 그 행만 "추가"가 되고, 뒤의 행들은 1단계에서 내용으로 짝이 맞아 "동일"로 남는다.

- 같은 키를 가진 행이 여러 개면 위에서부터 순서대로 짝짓는다.
- 3단계 유사도 = (공통 항목 수) ÷ (두 행 중 항목이 많은 쪽의 항목 수). 항목은 `SPEC=CON` 쌍, `KEY=VAL` 쌍, GOTO, REMARKS 단위이며 열 위치는 보지 않는다. 공통 항목이 2개 이상이어야 한다.

### 7.2 열 비교 — 쌍 정렬

`SPEC1/CON1 … SPEC20/CON20`, `KEY1/VAL1 … KEY20/VAL20`은 두 열을 한 쌍으로 묶어서 비교한다.
같은 번호끼리만 비교하면 중간에 쌍 하나가 끼어들었을 때 뒤쪽이 전부 "변경"으로 나오기 때문이다.

예) 과거 `[A, B, C]` → 최신 `[A, X, B, C]`

| 최신 위치 | 결과 |
|---|---|
| 1번 A | 동일 |
| 2번 X | 값 추가 (녹색) |
| 3번 B | 열 위치 이동 `← SPEC2` (남보라) |
| 4번 C | 열 위치 이동 `← SPEC3` (남보라) |

쌍의 짝은 ① 같은 위치·같은 값 → ② 다른 위치의 같은 값 → ③ 같은 위치에서 앞 항목(SPEC/KEY)만 같음 → ④ 다른 위치에서 앞 항목만 같음 → ⑤ 나머지 순으로 찾는다.

ADDR, GOTO, REMARKS는 쌍이 아니므로 같은 열끼리 그대로 비교한다.

### 7.3 값 정규화

비교 전에 값을 아래 규칙으로 다듬는다. 화면에 보이는 값도 다듬은 뒤의 값이다.

| 열 | 규칙 |
|---|---|
| 전체 | 앞뒤 공백 제거, NULL은 빈 값 |
| ADDR, VAL, GOTO | `-` 한 글자만 있으면 빈 값으로 처리. 값 안의 하이픈은 유지 |
| SPEC, CON, KEY, REMARKS | 하이픈(`-`)을 모두 제거 |

SPEC 값이 `EL_`로 시작하면 코드명을 찾아 `EL_xxx (코드명)` 형태로 덧붙여 보여준다. 코드명은 표시용이고 비교에는 쓰지 않는다.

### 7.4 서버 응답 형식 (`POST /diff/findPIDLineDiff`)

요청 파라미터: `pid`, `pidOid`(과거 HOUID), `pidOidb`(최신 HOUID)

```json
{
  "columns": ["ADDR", "SPEC1", "CON1", "...", "GOTO", "REMARKS"],
  "summary": {
    "added": 1, "modified": 3, "deleted": 0, "equal": 120, "total": 124,
    "changedCells": 7, "moved": 0, "fuzzy": 1, "shiftOnly": 1,
    "beforeCount": 123, "afterCount": 124
  },
  "rows": [
    {
      "status": "MODIFIED",
      "addr": "A100", "noBefore": "12", "noAfter": "13",
      "nChg": 2, "nMov": 4, "shiftOnly": false,
      "moved": true, "fuzzy": true,
      "cells": {
        "VAL1":  { "b": "10", "a": "11", "c": true, "t": "chg" },
        "SPEC3": { "b": "B",  "a": "B",  "c": true, "t": "mov", "f": "SPEC2" },
        "SPEC1": { "b": "A",  "a": "A",  "c": false }
      }
    }
  ]
}
```

| 필드 | 의미 |
|---|---|
| `b` / `a` | 과거 값 / 최신 값 |
| `c` | 차이 여부 |
| `t` | `chg` 값 변경, `add` 값 추가, `del` 값 삭제, `mov` 열 위치 이동 |
| `f` | 과거 값이 있던 열 (위치가 다를 때만) |
| `moved`, `fuzzy` | 해당될 때만 포함 |
| `nChg`, `nMov`, `shiftOnly` | 수정 행에만 포함 |

## 8. 미흡한 점 / 알려진 한계

### 8.1 비교 정확도

| # | 내용 | 영향 | 개선 방향 |
|---|---|---|---|
| 1 | **ADDR이 밀리는 값이면 삽입 지점 이후가 전부 "수정"으로 나온다.** 행을 중간에 넣을 때 뒤 행들의 ADDR이 다시 매겨지는 데이터라면, 1단계는 ADDR이 달라 실패하고 2단계에서 밀린 ADDR끼리 엉뚱한 행이 짝지어진다. GOTO가 ADDR을 가리키면 GOTO도 같이 차이로 잡힌다. | 가장 큼. ADDR 성격을 아직 확인하지 못함 | 1·2단계 사이에 "ADDR을 뺀 내용이 같은 행" 매칭 단계 추가. 단, 내용이 똑같은 행이 여러 개인 데이터에서는 짝이 달라질 수 있어 ADDR 성격 확인 후 적용 |
| 2 | **실제 데이터 검증을 하지 않았다.** 컴파일, JS 문법 검사, 샘플 값으로 쌍 정렬·순서 변경 감지만 확인했다. 브라우저 화면과 DB 연동은 미확인. | 화면 깨짐이나 예상 밖 매칭이 있을 수 있음 | 변경 내용을 아는 버전 쌍 몇 개로 결과 대조 |
| 3 | **쌍의 열 순서는 의미가 없다고 가정했다.** SPEC/CON, KEY/VAL 쌍이 다른 번호로 옮겨가도 "열 위치 이동"으로만 표시하고 변경 셀 수에 넣지 않는다. | 순서 자체가 의미 있는 로직이면 실제 변경을 가볍게 보이게 함 | 순서가 의미 있다면 이동도 변경으로 집계하도록 옵션화 |
| 4 | **유사도 기준이 60%로 고정**이고 화면에서 바꿀 수 없다. 항목이 1개뿐인 행은 유사 매칭 대상에서 빠진다. | 값이 비슷한 다른 행끼리 짝지어지거나, 많이 바뀐 행이 삭제+추가로 갈라질 수 있음 | 기준값 조정 UI 또는 `유사` 행만 모아 보는 필터 |
| 5 | 짝 없는 행이 많아 (과거 미매칭 × 최신 미매칭)이 200만을 넘으면 **유사 매칭을 통째로 건너뛴다.** 건너뛰었다는 표시는 없다. | 거의 다른 두 버전을 비교하면 조용히 삭제+추가로만 나옴 | 생략 여부를 응답에 담아 화면에 안내 |
| 6 | **하이픈 제거 정규화**: SPEC/CON/KEY/REMARKS는 하이픈을 모두 지우고 비교한다. `A-B`와 `AB`가 같은 값이 되고, 화면에도 하이픈이 빠진 값이 나온다. (기존 동작 유지) | 하이픈만 달라진 변경은 찾지 못함 | 표시는 원본 값, 비교만 정규화 값으로 분리 |
| 7 | 같은 ADDR이 여러 행이면 **위에서부터 순서대로** 짝짓는다. 내용이 더 비슷한 짝을 고르지 않는다. | 중복 ADDR 구간에서 변경이 실제보다 많아 보일 수 있음 | 같은 ADDR 묶음 안에서 유사도 우선 매칭 |
| 8 | **순서만 바뀐 동일 행**은 "동일"로 분류된다. `순서` 태그는 붙지만 변경 이동(N/P) 대상이 아니고, 동일 칩을 끄면 같이 숨겨진다. | 행 순서 변경만 따로 찾아보기 어려움 | "순서 변경" 필터 칩 추가 |
| 9 | 글자 단위 강조는 **앞뒤 공통 부분을 뺀 가운데 한 덩어리**만 표시한다. 한 값 안에서 두 군데가 바뀌면 그 사이 전체가 강조된다. | 긴 값에서 정확한 변경 위치 파악이 어려움 | 문자 단위 diff 알고리즘 적용 |

### 8.2 서버 / 성능

| # | 내용 | 영향 | 개선 방향 |
|---|---|---|---|
| 10 | **DB 조회 오류가 "결과 없음"으로 보인다.** `readVersion`이 예외를 로그만 찍고 빈 목록을 돌려준다. | DB 장애를 데이터 없음으로 오해 | 예외를 올려 화면에 오류로 표시 |

### 8.3 화면 / 사용성

| # | 내용 | 영향 | 개선 방향 |
|---|---|---|---|
| 15 | **엑셀(xlsx) 내보내기가 아니다.** CSV라서 색·강조가 없고, 열 이동의 과거 위치(`← SPEC2`)도 빠진다. | 보고용으로 쓰려면 재가공 필요 | 색상 포함 xlsx 내보내기 |
| 16 | **주소로 결과를 공유할 수 없다.** PID·버전이 URL에 남지 않아 새로고침하면 처음부터 다시 조회해야 한다. | 비교 결과 공유·재확인이 번거로움 | `?pid=&base=&comp=` 파라미터 지원 |
| 17 | **버전 자동 선택이 없다.** 목록을 불러온 뒤 과거·최신을 항상 직접 골라야 한다. | 최신 두 버전 비교가 대부분이라면 클릭이 늘어남 | 최신 2개 자동 선택 (목록 정렬 기준 확인 필요) |
| 18 | **정렬·열 폭 조절이 없다.** ADDR 폭은 150px 고정, 일반 셀은 최대 420px에서 말줄임. | 긴 값은 상세 패널을 열어야 전체 확인 가능 | 열 폭 드래그, 셀 줄바꿈 옵션 |
| 19 | **검색어 강조가 없다.** 검색은 행만 걸러내고 어느 셀에서 걸렸는지는 표시하지 않는다. | 열이 많으면 일치 위치를 눈으로 찾아야 함 | 일치 셀 강조 및 가로 스크롤 |
| 20 | **행을 키보드로 고를 수 없다.** 변경 행 이동(N/P)만 되고, 화살표 키 이동이나 Tab 포커스는 없다. | 키보드만 쓰는 사용자는 동일 행 상세를 열 수 없음 | 행 포커스·화살표 이동 지원 |
| 21 | `Ctrl`+클릭 **다중 강조는 표시만** 된다. 여러 행을 나란히 비교하는 기능은 없다. | 강조 외 용도가 없음 | 선택 행만 보기 필터 |
| 22 | **다크모드는 확인하지 못했다.** 색 값만 정의했고 실제 화면 대비는 미검증. 화면 안에 전환 버튼도 없어 다른 화면에서 저장한 설정을 따른다. | 다크모드에서 가독성 문제 가능 | 실기 확인 후 색 보정 |
| 23 | **두 버전 비교만 된다.** 세 버전 이상의 변경 이력을 한 번에 볼 수 없다. | 버전 여러 개를 추적하려면 반복 조회 | 버전 이력 타임라인 |

### 8.4 우선순위 제안

1. **#1 ADDR 성격 확인** — 밀리는 값이면 가장 큰 문제였던 "뒤가 전부 변경으로 나오는" 현상이 그대로 남는다.
2. **#2 실제 데이터 검증** — 변경 내용을 아는 버전 쌍으로 결과를 대조한다.
3. **#10 DB 오류 표시**, **#3 쌍 순서 가정 확인** — 결과를 잘못 믿게 만들 수 있는 항목.
4. 이후 #15(xlsx), #16(URL 공유), #12(대량 행 성능) 순.
