> 이 파일은 전체 조건 양식과 상세 규칙을 담은 **레퍼런스**다.
> 참조 명세서 : `docs/제품자재_BOM조회_명세서.md`
> 재현 대상 : `/dash/searchPartAnalysis` 화면 → `POST /dash/searchMissPartofProduct`

## 1. 사용법

1. 아래 **2장의 프롬프트 블록 전체**를 복사한다.
2. `←` 표시가 붙은 항목을 채운다. **쓰지 않는 조건은 반드시 `-` 로 남긴다.** (지우지 말 것)
3. 그대로 붙여넣어 요청한다.

> **왜 양식이 필요한가**
> 화면 로직에는 자연어로 말하지 않으면 절대 드러나지 않는데 결과를 바꾸는 동작이 3가지 있다.
>
> | 화면 로직 | 말하지 않으면 |
> |---|---|
> | `년도` 미지정 시 **`2025` 로 고정** | 당해년도로 조회되어 결과가 완전히 달라짐 |
> | `제품상태` 값이 있기만 하면 **무조건 `RLS`** | 상태 조건이 빠져 건수가 더 많이 나옴 |
> | 조회 컬럼이 **고정 세트** | 명세서 지침상 요청한 컬럼만 나와 그리드와 달라짐 |

## 2. 복붙용 프롬프트 (전체 복사)

```
[제품-자재(BOM) 사용처 조회]
docs/제품자재_BOM조회_명세서.md 기준으로 SQL을 생성하고 실행해줘.
재현모드: 화면동일        ← searchPartAnalysis 화면과 결과가 동일해야 함

■ 필수 (반드시 채울 것)
- 년도(제품 수정일 MD$MDATE 기준): 2026        ← 생략 금지. 비우면 화면은 2025로 동작함
- 제품상태: 릴리즈(RLS)만                       ← "릴리즈(RLS)만" 또는 "전체"
- 자재번호(Part No.): 2117040001                ← 자재번호/블록번호 중 최소 1개는 필수
- 블록번호(Block No.): -

■ 선택 조건 (안 쓰면 '-' 로 둘 것. '-' 와 빈 값은 조건을 만들지 않음)
- CMT(적용조건, 부분일치): -
- SPEC(부분일치): -
- 브랜드(EL_ABRAND): -
- 생산거점 EL_ASPSCD: -
- 기종 EL_ATYP: -
- 관통 EL_ETHRU: -
- 전망 EL_COB: -
- WALL구조 EL_BWALLT: -
- 기계구조 최초설계일 EL_ZFDA: -    (연산자: - , 값: -)
- 전기구조 최초설계일 EL_ZFDC: -    (연산자: - , 값: -)
- 추가 사양조건(kv): -              ← 예) EL_ECAA like %1600% / EL_ECCB = 1350 (3.1 참고)
- 값 없이 컬럼만 추가: -            ← 예) EL_ECCA, EL_ECHH

■ 출력
- 화면 기본 그리드 컬럼 전체
  (PARENTNO, PARENT_VER, PROD_STATUS, PROD_MODDATE, GISONG, BRAND, EL_ASPD,
   ASPSCD, EL_ACAPA, PARTNO, PARTNAME, PART_VERSION, SPEC, GLCODE, PART_QTY,
   CMT, BLOCKNO, BLOCK_OPT, UCHECK) + 위에 적은 kv 코드
- ORDER BY 없음 (원본 쿼리와 동일)

■ 지켜야 할 규칙
1. TEST%, Q% 제품 제외 조건과 WITH ouid 골격은 변경하지 말 것
2. '-' 또는 빈 값 항목은 조건을 만들지 말 것
3. 년도를 내가 적지 않았으면 임의로 만들지 말고 되물을 것
4. 조회 결과 앞에 "적용 연도 / 제품상태 / 적용 조건" 을 한 줄로 요약해서 알려줄 것
```

## 3. 항목 채우는 법

| 항목 | 입력 예 | 동작 |
|---|---|---|
| 년도 | `2026` | 제품 **수정일(MD$MDATE)** 연도. 등록일·승인일 아님 |
| 제품상태 | `릴리즈(RLS)만` / `전체` | `릴리즈(RLS)만` → `MD$STATUS = 'RLS'` 추가 |
| 자재번호 | `2117040001` | 완전일치 |
| 자재번호 | `2117*` | `*` → `%` 치환 후 `LIKE '2117%'` |
| 블록번호 | `P117040` | **완전일치만.** 자동으로 대문자 변환됨 (`*` 안 됨) |
| CMT | `OPT-A` | 대소문자 무시 부분일치 |
| SPEC | `SS400` | 대문자 변환 후 부분일치 |
| 브랜드 | `HDEL` / `HD*` | `*` 사용 가능 |
| EL_ASPSCD (생산거점) | `KR00` | **완전일치만** |
| EL_ATYP (기종) | `MRL` / `MRL*` | `*` 사용 가능 |
| EL_ETHRU (관통) | `Y` | **완전일치만** |
| EL_COB (전망) | 코드값 / `값*` | `*` 사용 가능 |
| EL_BWALLT (WALL 구조) | 코드값 / `값*` | `*` 사용 가능 |
| EL_ZFDA / EL_ZFDC | 값 `20260101`, 연산자 `>=` | `YYYYMMDD` 문자열 비교. 연산자는 `=` `>=` `>` `<=` `<` |
| 추가 사양조건(kv) | `EL_ECAA like %1600%` | 화면의 **동적 조건** 영역. 작성법은 **3.1 참고** |
| 값 없이 컬럼만 추가 | `EL_ECCA, EL_ECHH` | 조건은 안 걸고 **조회 컬럼으로만** 추가. **3.1 참고** |

- 사양 코드값(브랜드/기종/생산거점 등)은 **화면 콤보에 보이는 표시값 그대로** 적는다. (`COD()` 변환값과 비교하기 때문)
- 조건이 늘수록 조회가 느려진다. 필요한 사양만 적는다.

## 3.1 동적조건(kv) 작성법

화면 하단 **동적 조건** 영역의 한 행은 `[Key] [연산자] [Value]` 구조다.
프롬프트에서는 **한 줄에 한 행**씩, `KEY 연산자 값` 형식으로 ` / ` 로 구분해 적는다.

```
- 추가 사양조건(kv): EL_ECAA like %1600% / EL_ECCB = 1350 / EL_ECHH != 2100
- 값 없이 컬럼만 추가: EL_ECCA, EL_ECWSF
```

### 3.1.1 연산자 대응표

| 화면 드롭다운 | 프롬프트 표기 | 생성 SQL |
|---|---|---|
| `Like  (포함)` — **화면 기본 선택값** | `like` | `LIKE '값'` |
| `Not Like  (미포함)` | `notlike` | `notlike '값'` → **Oracle 문법 오류. 3.1.2 의 2번 참고** |
| `=  Equal  (일치)` | `=` | `= '값'` |
| `!=  Not Equal  (불일치)` | `!=` | `!= '값'` |

### 3.1.2 반드시 알아야 할 3가지

1. **`%` 가 자동으로 붙지 않는다.**
   화면 Value 칸에 `1600` 만 넣으면 `LIKE '1600'` 이 되어 사실상 완전일치다.
   부분일치를 원하면 프롬프트에도 `EL_ECAA like %1600%` 처럼 **`%` 를 직접** 쓴다.

2. **`Not Like` 는 화면에서 항상 0건이다.**
   화면 select 값 `notlike` 가 그대로 SQL에 붙어 `... ) notlike '값'` 이 되는데, Oracle에는 `notlike` 연산자가 없다.
   쿼리가 실패하고 예외를 삼켜 **빈 배열**이 반환된다.
   실제로 "미포함" 조회를 하려면 아래처럼 요청한다.
   ```
   재현모드: 데이터정확
   - 추가 사양조건(kv): EL_COB not like %PANO%   (NOT LIKE 로 올바르게 작성해줘)
   ```

3. **Value 를 비우면 조건이 아니라 출력 컬럼만 추가된다.**
   화면은 Key만 입력해도 행을 수집하고, 값이 없으면 `WHERE` 조건을 만들지 않는다.
   프롬프트에서는 `추가 사양조건(kv)` 이 아니라 **`값 없이 컬럼만 추가`** 항목에 적는다.

### 3.1.3 그 밖의 동작

- 조건에 쓴 Key 는 화면 그리드에 **컬럼으로도 자동 추가**된다. (중복 제거, 입력 순서 유지)
  화면과 컬럼까지 맞추려면 프롬프트 출력 항목에 `kv 코드는 출력 컬럼에도 포함` 이라고 적는다.
- Key 는 `ELV_INFO$VF` 의 `EL_xxxx` 컬럼명을 그대로 쓴다. (예: `EL_ECAA`, `EL_ECCB`, `EL_ECWSF`)
- **`재현모드: 화면동일` 일 때 조건절은 치수형 코드까지 전부 `COD()` 로 감싸진다.**
  치수값이 기대와 다르게 걸러질 수 있으므로, 치수 조건이 핵심이면 `재현모드: 데이터정확` 을 쓴다.
  (명세서 15장 14번)

### 3.1.4 작성 예시

| 하고 싶은 것 | 프롬프트 표기 |
|---|---|
| CAR 외부가로에 `1600` 이 포함된 호기 | `- 추가 사양조건(kv): EL_ECAA like %1600%` |
| CAR 내부세로가 정확히 `1350` | `- 추가 사양조건(kv): EL_ECCB = 1350` |
| 두 조건 동시 적용 | `- 추가 사양조건(kv): EL_ECAA like %1600% / EL_ECCB = 1350` |
| 조건 없이 값만 확인 | `- 추가 사양조건(kv): -`<br>`- 값 없이 컬럼만 추가: EL_ECCA, EL_ECHH, EL_ECWSF` |
| 전망 종류가 `PANO` 가 아닌 호기 | `재현모드: 데이터정확` + `- 추가 사양조건(kv): EL_COB not like %PANO%` |

## 4. 자주 쓰는 요청 예시

### 4.1 특정 자재를 쓰는 제품 찾기 (가장 기본)

```
docs/제품자재_BOM조회_명세서.md 기준, 재현모드 화면동일로
2026년 수정 제품 중 릴리즈(RLS)만 대상으로, 자재번호 2117040001 을 사용하는 제품 목록을
화면 기본 그리드 컬럼 전체로 조회해줘. ORDER BY 는 넣지 마.
```

### 4.2 블록번호 + 기종 조건

```
docs/제품자재_BOM조회_명세서.md 기준, 재현모드 화면동일로
2026년, 릴리즈만, 블록번호 P117040, 기종 MRL 조건으로 조회해줘.
화면 기본 그리드 컬럼 전체로 보여주고 ORDER BY 는 넣지 마.
```

### 4.3 자재번호 앞자리 + CMT 부분일치

```
docs/제품자재_BOM조회_명세서.md 기준, 재현모드 화면동일로
2026년, 릴리즈만, 자재번호 2117* , CMT 에 OPT-A 가 포함된 BOM 을
화면 기본 그리드 컬럼 전체로 조회해줘.
```

### 4.4 치수 사양 조건 + 컬럼 추가

```
docs/제품자재_BOM조회_명세서.md 기준, 재현모드 화면동일로
2026년, 릴리즈만, 자재번호 2117040001,
추가 사양조건 EL_ECAA like %1600%,
EL_ECCA 와 EL_ECHH 는 조건 없이 컬럼으로만 추가해서 조회해줘.
```

### 4.5 기계구조 최초설계일 기준

```
docs/제품자재_BOM조회_명세서.md 기준, 재현모드 화면동일로
2026년, 릴리즈만, 블록번호 P117040,
기계구조 최초설계일(EL_ZFDA) 이 20260101 이상인 건만 조회해줘.
```

### 4.6 집계 (화면에는 없는 조회)

집계는 화면 기능이 아니므로 `재현모드: 화면동일` 을 쓰지 않는다.

```
docs/제품자재_BOM조회_명세서.md 기준으로,
2026년 제품(TEST/Q 제외) 중 블록번호 P117040 자재들의
자재별 사용 제품 수를 많이 쓰이는 순으로 집계해줘.
제품 수는 COUNT(DISTINCT PE.PRODUCTOUID) 로 셀 것.
```

#### 4.7.2 설계변경 영향도 분석 (블록 + 최초설계일)

```
docs/제품자재_BOM조회_명세서.md 기준, 재현모드 화면동일로

■ 분석 요청
- 이 블록에서 실제로 쓰이는 자재(PARTNO)가 몇 종인지, 각각 몇 개 호기에 들어가는지
- 사용 호기 수가 많은 자재 상위 10건을 표로 (자재번호 / 자재명 / 사용 호기 수)
- 반대로 호기 1대에만 쓰이는 단발성 자재도 따로 목록화
- 설계변경 시 영향받는 호기 번호(PARENTNO) 전체 목록을 마지막에 나열
- 집계는 COUNT(DISTINCT PE.PRODUCTOUID) 기준으로 셀 것
```


#### 4.7.6 분석 요청 시 공통 요령

1. `재현모드: 화면동일` 은 **조회 결과를 화면과 맞춰야 할 때만** 쓴다. 집계·순위 분석은 화면 기능이 아니므로 뺀다.
2. 제품 수를 세는 지시는 항상 **`COUNT(DISTINCT PE.PRODUCTOUID)`** 로 명시한다.
   조회 단위가 "제품 × 자재" 1행이라 `COUNT(*)` 를 쓰면 건수가 부풀려진다. (명세서 15장 1번)
3. 마지막에 **"적용 연도 / 제품상태 / 적용 조건 요약"** 을 요구해 두면,
   년도가 `2025` 로 기본 적용되는 사고를 바로 잡아낼 수 있다.

## 5. 결과 확인 체크리스트

답변을 받았을 때 아래를 확인한다.

- [ ] 적용된 **연도**가 내가 지정한 값인가 (미지정 시 `2025` 가 적용됐을 수 있음)
- [ ] **제품상태** 조건이 의도대로인가 (`릴리즈(RLS)만` → `MD$STATUS = 'RLS'`)
- [ ] SQL에 `NOT LIKE 'TEST%'`, `NOT LIKE 'Q%'`, `WITH ouid` 골격이 그대로 있는가
- [ ] 내가 `-` 로 둔 항목이 조건으로 들어가지 않았는가
- [ ] `*` 를 쓴 항목이 `LIKE` 로 변환됐는가
- [ ] 조회 컬럼이 화면 그리드와 같은가

---

## 6. 결과가 0건일 때 확인할 것

1. **연도** — 제품 *수정일* 기준이다. 등록만 되고 수정이 없던 제품은 해당 연도에 안 잡힌다.
2. **제품상태** — `릴리즈(RLS)만` 을 걸면 작업중(WIP) 제품이 모두 빠진다.
3. **TEST / Q 호기** — `TEST%`, `Q%` 로 시작하는 제품번호는 **항상 제외**된다. 테스트 호기는 이 조회로 찾을 수 없다.
4. **영업사양 미등록 제품** — 브랜드/기종 등 사양 조건을 걸면 영업사양이 없는 제품은 결과에서 빠진다.
5. **자재번호 자릿수·대소문자** — 블록번호와 SPEC은 대문자로 변환되어 비교된다.
6. 원본 로직은 오류가 나도 **빈 배열**을 반환한다. 0건이 "데이터 없음"인지 "쿼리 오류"인지 구분되지 않으므로, 위 조건을 하나씩 빼면서 재조회한다.

## 7. 참고 : 알려진 코드-명세서 불일치

`재현모드: 화면동일` 로 요청하면 아래는 자동으로 화면 동작에 맞춰진다. 직접 SQL을 쓸 때만 주의한다.

| 항목 | 내용 |
|---|---|
| CMT 조건 | 원본 코드는 `UPPER(PE.CMT)` 가 아니라 `REGEXP_REPLACE(PE.CMT, '[a-z]', UPPER('\0'))` 를 쓴다. 실제로는 **소문자를 제거하는** 동작이라 `UPPER()` 기반 SQL과 결과가 다를 수 있다. (명세서 15장 13번) |
| kv 조건의 `COD()` | SELECT 절은 치수형 코드(`EL_ECAA` 등)에 `COD()` 를 쓰지 않지만, WHERE 절은 **모든 코드에 `COD()` 를 적용**한다. 치수형에 값 조건을 걸 때 결과가 어긋날 수 있다. (명세서 15장 14번) |
| `EL_ETHRU` 응답 | API 응답의 `el_ETHRU` 는 **매핑 누락으로 항상 빈 문자열**이다. 조건으로는 정상 동작한다. (명세서 14.2) |
