# 수배로직 Docs 사용 매뉴얼

> 사내 문서 시스템(**TeamDocs / 수배로직 Docs**) 사용법입니다.
> **DB 명세서 · API 정의서 · 팀 규칙**을 이 화면에서 직접 만들고, 마크다운으로 작성하고, 팀원과 공유합니다.
>
> - 화면 주소 : `http://localhost:8070/dash/viewLogic` (운영 : `https://vault-in.hdel.co.kr:8070/dash/viewLogic`)
> - 화면 파일 : `src/main/resources/templates/thymeleaf/logic/readDBFile.html`
> - 최종 수정 : 2026-09-04

## 0. 30초 요약 (이것만 지켜주세요)

| 해야 할 일 | 방법 |
|---|---|
| 새 문서 분류를 만든다 | 사이드바 **명세서** 헤더의 `📁+` (카테고리 추가) |
| 문서를 만든다 | 카테고리 이름 줄의 `+` 버튼 |
| 하위 문서를 만든다 | 문서 이름 줄에 마우스를 올린 뒤 `+` 버튼 |
| 내용을 쓴다 | 문서 열기 → 우측 상단 **편집** → 마크다운 작성 → **저장**(`Ctrl+S`) |
| API 주소가 필요하다 | 문서 제목 바로 아래 **"이 문서 조회 API"** 카드에서 **복사** |

> ⚠️ **가장 중요** — 팀원과 공유되는 문서는 사이드바 위쪽 **명세서** 영역(카테고리 + 명세서)뿐입니다.
> 사이드바 **맨 아래 파란색 `새 문서 작성` 버튼으로 만든 문서는 내 브라우저(localStorage)에만 저장되어 다른 사람에게 보이지 않습니다.**
> 업무 문서는 반드시 **명세서 영역**에 만들어 주세요. → [9. 헷갈리는 두 영역](#9-헷갈리는-두-영역-명세서-vs-새-문서-작성)

## 1. 화면 구성

```
┌───────────────────────────┬────────────────────────────────────────────────┐
│ TeamDocs                  │  [브레드크럼]         [편집] [새로고침] [🌙]  │ ← 상단바
├───────────────────────────┼────────────────────────────────────────────────┤
│ 🔍 문서 검색…              │  # 문서 제목                                   │
│                           │  ┌──────────────────────────────────────────┐  │
│ 명세서             [📁+]  │  │ GET   이 문서 조회 API                   │  │ ← ★ API 카드
│  ▼ 📁 DB 명세서  [+][✏][🗑]│  │ /api/getLogicVerifyAsDB?…    [복사] [↗] │  │
│      📄 ECO 검증          │  └──────────────────────────────────────────┘  │
│    ▼ 📄 로직 작성         │                                                │
│        📄 작성_김영환     │  본문(마크다운 렌더링)…                        │
│        📄 작성_김지현     │                                                │
│  ▶ 📁 API 정의서          │                                    [이 문서    │
│  ▶ 📁 기타 규칙           │                                     목차]      │
│ ─────────────────────     │                                                │
│ (개인 문서 트리)          │                                                │
├───────────────────────────┤                                                │
│ [ + 새 문서 작성 ]        │  ← 개인용(localStorage). 업무 문서 금지         │
│ [카테고리] [⬇] [⬆]        │                                                │
└───────────────────────────┴────────────────────────────────────────────────┘
```

| 영역 | 설명 |
|---|---|
| **사이드바 상단 – 명세서** | 팀 공용 문서. DB(`PLM_DOC_MENU`)에 저장되어 **모두에게 공유**됩니다. |
| **사이드바 하단 – 문서 트리** | 개인 메모용. **내 브라우저에만** 저장됩니다. |
| **상단바** | 현재 위치(브레드크럼), 편집 / 새로고침 버튼, 다크모드 전환 |
| **본문** | 마크다운 렌더링 결과 + 이 문서의 **조회 API 카드** |
| **오른쪽 목차** | 본문의 H1~H3 제목으로 자동 생성 (제목이 2개 이상일 때 표시) |

## 2. 기본 개념 3가지

### ① 카테고리(대분류)

`DB 명세서`, `API 정의서`, `기타 규칙` 같은 최상위 묶음입니다.
사이드바 **명세서** 글자 옆 `📁+` 버튼으로 **누구나 직접 추가**할 수 있습니다.

### ② 명세서(문서)

카테고리 안에 들어가는 실제 문서 한 건입니다. 내용은 **마크다운**으로 작성합니다.

### ③ 하위 명세서

명세서 아래에 또 명세서를 넣을 수 있습니다. **깊이 제한은 없습니다.**

```
DB 명세서 (카테고리)
 └─ 로직 작성 (명세서)
     ├─ 작성_김영환 (하위 명세서)
     ├─ 작성_김지현
     └─ 작성_이지은
```

> 💡 **문서 코드(ID)** 는 저장 시 서버가 `SPEC00001`, `SPEC00002` … 순번으로 자동 발급합니다.
> 이 코드가 곧 API 주소의 `type=` 값이 되고, 본문이 저장되는 위치(`PLM_LLM_METADATA.CATEGORY`)가 됩니다.
> **직접 정할 필요도, 외울 필요도 없습니다.**

## 3. 카테고리 만들기

1. 사이드바 **명세서** 글자 오른쪽 `📁+` (카테고리 추가) 클릭
2. 이름 입력 (예: `설비 명세서`) → 확인
3. 사이드바에 새 카테고리가 바로 생기고, **DB에 즉시 저장**됩니다.

- 색상(파랑 / 보라 / 주황)은 순서대로 자동 배정됩니다.
- 아이콘을 바꾸려면 카테고리 이름 위에 마우스를 올려 `✏`(이름 변경) → 이름 확인 → 이어서 뜨는 **아이콘** 입력창에 lucide 이름 입력 → [7. 아이콘 지정하기](#7-아이콘-지정하기)

> ✅ **팀 운영 원칙** — 앞으로 DB 명세서는 **각자 필요한 카테고리를 직접 만들고 그 안에 문서를 작성**하면 됩니다.
> 관리자에게 요청하거나 소스(`api.js`)를 수정할 필요가 없습니다.

## 4. 명세서(문서) 만들기

### 카테고리 바로 아래에 만들기

1. 카테고리 이름 줄의 `+` 버튼 클릭
2. 문서 이름 입력 (예: `자재 마스터 테이블 정의서`) → 확인
3. 문서가 생성되고 **바로 열립니다.**

### 하위 문서로 만들기

1. 상위가 될 **문서 이름 줄에 마우스를 올립니다** → 오른쪽에 `+` `✏` `🗑` 버튼이 나타납니다.
2. `+` 클릭 → 이름 입력
3. 상위 문서 아래에 들여쓰기되어 추가됩니다.

> 🔔 **하위 문서가 있는 문서는 이름을 클릭해도 본문이 열리지 않고 접기/펼치기만 됩니다.**
> 상위 문서에도 내용을 쓰고 싶다면 그 아래에 `개요` 같은 하위 문서를 하나 만들어 쓰는 편이 좋습니다.

### 새로 만든 문서는 바로 편집 가능

문서를 만들면 서버가 **조회 API / 저장 API 주소를 자동으로 연결**해 줍니다.
따라서 생성 직후 **편집** 버튼이 활성화되고, 저장하면 DB에 바로 반영됩니다.

## 5. 문서 작성 · 저장

1. 사이드바에서 문서를 클릭해 엽니다.
2. 오른쪽 위 `✏ 편집` 클릭
3. 화면이 좌우로 나뉩니다 — **왼쪽: 마크다운 입력 / 오른쪽: 실시간 미리보기**
4. **작성자** 칸에 본인 이름을 적어 주세요. (비우면 `미상`으로 저장)
5. `저장` 버튼 또는 `Ctrl + S`

| 항목 | 동작 |
|---|---|
| 제목 | 명세서 편집에서는 **수정 불가**(회색). 제목 변경은 사이드바의 `✏` 이름 변경으로 |
| 카테고리 선택 | 명세서 편집에서는 숨겨집니다 (카테고리 이동은 14. FAQ 참고) |
| 취소 | 저장하지 않고 원래 문서로 돌아갑니다 |
| 저장 후 | DB에서 다시 읽어와 화면을 갱신합니다 |

> ⚠️ **자동 저장은 없습니다.** 긴 문서를 쓸 때는 중간중간 `Ctrl + S` 를 눌러 주세요.
>
> ⚠️ **동시 편집 보호 기능이 없습니다.** 같은 문서를 두 사람이 동시에 편집하면 **나중에 저장한 내용이 앞선 내용을 덮어씁니다.**
> 한 문서는 담당자를 정하거나, 사람별로 하위 문서를 나눠 쓰는 것을 권장합니다. (예: `작성_김영환`, `작성_김지현`)

## 6. API 사용법 — 화면 상단(문서 제목 아래) 카드를 사용하세요

**API 주소를 직접 만들거나 외우지 마세요.** 문서를 열면 제목 바로 아래에 그 문서 전용 API 카드가 나옵니다.

```
┌──────────────────────────────────────────────────────────────────┐
│ GET   이 문서 조회 API                                           │
│       /api/getLogicVerifyAsDB?key=subae&type=SPEC00007  [📋] [↗] │
└──────────────────────────────────────────────────────────────────┘
```

| 버튼 | 동작 |
|---|---|
| 📋 **복사** | 현재 서버 기준 **전체 주소**(`http://…`)를 클립보드에 복사합니다. 그대로 붙여 넣어 쓰면 됩니다. |
| ↗ **새 탭에서 열기** | 새 탭에서 응답(마크다운 원문)을 바로 확인합니다. |

### 이 API가 돌려주는 것

- **응답 본문 = 마크다운 원문 그대로** (JSON 래핑 없음)
- 다른 시스템 · 스크립트 · AI 에이전트에서 이 주소만 호출하면 최신 문서 내용을 받아갈 수 있습니다.

```bash
# 예시
curl "http://localhost:8070/api/getLogicVerifyAsDB?key=subae&type=SPEC00007"
```

### API 카드가 안 보이는 경우

조회 주소가 연결되지 않은 문서입니다(예전에 만들어 둔 목업 문서 등). 이런 문서의 본문은 **내 브라우저에만** 저장됩니다.
→ 새로 만들어 내용을 옮기거나, 담당자에게 `PLM_DOC_MENU.READ_URL` 등록을 요청하세요.

### 카테고리 자체의 API (문서 목록)

카테고리도 고유 주소를 가집니다. 그 안의 문서 목록과 문서별 조회/저장 주소를 함께 돌려줍니다.

```
GET /api/docmenu/group/{카테고리ID}?key=subae
```

### 전체 API 한눈에 보기

| 용도 | Method | 주소 | 비고 |
|---|---|---|---|
| 사이드바 메뉴 전체 조회 | GET | `/api/docmenu?key=subae` | `{ result, groups[], specs[] }` |
| 카테고리 내 문서 목록 | GET | `/api/docmenu/group/{id}?key=subae` | |
| 메뉴 추가 | POST | `/api/docmenu/create` | `menuType=GROUP` 또는 `SPEC` |
| 메뉴 이름·아이콘 변경 | POST | `/api/docmenu/update` | |
| 메뉴 삭제 | POST | `/api/docmenu/delete` | 하위가 있으면 `force=Y` |
| **문서 본문 조회** | GET | `/api/getLogicVerifyAsDB?key=subae&type={문서ID}` | ★ 상단 카드의 그 주소 |
| **문서 본문 저장** | POST | `/api/update_PLM_DB_MetaData?key=subae&type={문서ID}` | form 전송, 본문 파라미터 `updatedContent` |

> 🔑 모든 API는 인증 파라미터 `key=subae` 가 필요합니다. (사내망 전용)

## 7. 아이콘 지정하기

카테고리 · 문서 모두 [lucide](https://lucide.dev/icons) 아이콘을 쓸 수 있습니다.

1. 대상에 마우스를 올려 `✏`(이름 변경) 클릭
2. **이름 변경** 입력창 → 확인
3. 이어서 뜨는 **아이콘** 입력창에 아이콘 이름 입력

> - 이름은 **모두 소문자 + 하이픈** 입니다. (`scroll-text` ✅ / `ScrollText` ❌)
> - 비워 두면 기본값 — 카테고리 `folder`, 문서 `file-text`
> - 목록에 없는 이름을 넣으면 아이콘 자리가 **빈칸**으로 보입니다.

### 자주 쓰는 아이콘

| 분류 | 입력값 |
|---|---|
| 문서 · 폴더 | `folder` `folder-open` `folder-tree` `file-text` `files` `file-code` `file-spreadsheet` `book-open` `scroll-text` `clipboard-list` |
| 데이터 · 시스템 | `database` `table` `server` `hard-drive` `webhook` `plug` `network` `globe` `cpu` `layers` |
| 개발 · 업무 | `code` `terminal` `git-branch` `bug` `settings` `wrench` `package` `boxes` `factory` `users` |
| 상태 · 강조 | `rocket` `star` `bookmark` `flag` `alert-triangle` `check-circle` `shield` `lock` `calendar` `bar-chart-3` |

## 8. 이름 변경 · 삭제

문서 / 카테고리 줄에 마우스를 올리면 버튼이 나타납니다.

| 버튼 | 기능 |
|---|---|
| `+` | 하위 항목 추가 |
| `✏` | 이름 / 아이콘 변경 |
| `🗑` | 삭제 |
| `🔄` (카테고리 헤더) | 메뉴를 DB에서 다시 읽기 |

### 삭제 시 꼭 알아둘 것

- 하위 항목이 있으면 **"하위 N개도 함께 삭제됩니다"** 확인 창이 뜹니다.
- 삭제되는 것은 **메뉴(사이드바 항목)** 뿐이고, **작성한 본문은 DB(`PLM_LLM_METADATA`)에 그대로 남습니다.**
- 다만 화면에서 새로 만들면 **새 코드(`SPEC000xx`)가 발급**되므로 예전 본문이 자동으로 붙지는 않습니다.
  → 실수로 지웠다면 **직접 다시 만들지 말고, 문서 코드와 함께 DB 담당자에게 복구를 요청**하세요.

> 🚫 **다른 사람이 만든 문서 · 카테고리는 임의로 삭제하지 마세요.** 삭제 전 담당자에게 확인해 주세요.

## 9. 헷갈리는 두 영역 (명세서 vs 새 문서 작성)

| 구분 | **명세서** 영역 (사이드바 위쪽) | **새 문서 작성** 버튼 (사이드바 아래) |
|---|---|---|
| 저장 위치 | **DB** (`PLM_DOC_MENU` + `PLM_LLM_METADATA`) | **내 브라우저** localStorage |
| 팀원에게 보임 | ✅ 보입니다 | ❌ 나만 보입니다 |
| API로 조회 | ✅ 가능 (상단 카드) | ❌ 불가 |
| 브라우저 캐시 삭제 시 | 안전 | **내용이 사라집니다** |
| 용도 | **DB 명세서 / API 정의서 / 팀 규칙 등 모든 업무 문서** | 개인 메모, 임시 초안 |

**→ 업무 문서는 예외 없이 "명세서" 영역에 작성해 주세요.**

## 10. 문서 상태 배지 읽는 법

문서를 열면 제목 아래 메타 영역에 배지가 표시됩니다.

| 배지 | 의미 | 편집 가능? |
|---|---|---|
| 🟢 **DB 연결** | 본문을 DB에서 읽어오는 정상 상태 | ✅ (저장 주소도 있으면) |
| 🟠 **목업** | 조회 API가 연결되지 않아 내 브라우저에만 저장됨 | ✅ 하지만 **공유되지 않음** |
| 🔒 **읽기 전용** | 조회는 되지만 저장 주소가 없음 | ❌ 편집 버튼 비활성 |

- 사이드바 문서 이름 오른쪽의 **작은 초록 점**도 "DB 연결됨" 표시입니다.
- 화면에서 새로 만든 문서는 항상 **DB 연결 + 편집 가능** 상태입니다.

## 11. 그 밖의 기능

| 기능 | 사용법 |
|---|---|
| **검색** | 사이드바 위 검색창. 문서 이름은 물론 **하위 문서 이름까지** 찾아 해당 가지를 자동으로 펼쳐 보여줍니다. |
| **접기 / 펼치기** | 카테고리 이름 클릭 = 접기/펼치기. 문서 앞 `▸` 클릭 = 하위 목록 접기/펼치기 |

| **다크 모드** | 상단바 맨 오른쪽 🌙 / ☀ 버튼 (선택은 브라우저에 기억됨) |
| **목차** | 화면이 넓을 때 오른쪽에 자동 표시. 제목을 클릭하면 해당 위치로 이동 |
| **저장 단축키** | `Ctrl + S` (편집 화면에서만 동작) |
| **JSON 내보내기 / 가져오기** | 사이드바 하단 `⬇` `⬆` — **개인 문서 트리 전용**입니다. 명세서는 대상이 아닙니다. |

## 14. 문제 해결 (FAQ)

**Q. "메뉴를 DB에서 불러오지 못해 기본 목록으로 표시합니다" 토스트가 떠요.**
A. 서버가 꺼져 있거나 `PLM_DOC_MENU` 테이블이 없는 경우입니다. 이때 화면은 `api.js` 의 기본 목록으로 대체되어 뜨며, **이 상태에서 추가/수정하면 DB에 저장되지 않습니다.**
→ 서버 상태를 확인하고, 테이블이 없다면 `src/main/resources/sql/PLM_DOC_MENU.sql` 을 한 번 실행하면 됩니다(재실행해도 안전).

**Q. 편집 버튼이 회색(자물쇠)으로 눌리지 않아요.**
A. 저장 주소가 없는 **읽기 전용** 문서입니다. 화면에서 새로 만든 문서는 이 상태가 되지 않습니다. 예전 문서라면 담당자에게 `PLM_DOC_MENU.SAVE_URL` 등록을 요청하세요.

**Q. 문서를 클릭했는데 본문이 안 열려요.**
A. **하위 문서를 가진 문서**는 클릭 시 접기/펼치기만 동작합니다. 하위 문서를 선택하세요.

**Q. 저장했는데 다른 사람 화면에 안 보여요.**
A. 상대방 화면에서 카테고리 헤더의 `🔄` 또는 상단바 `🔄` 를 눌러 다시 불러오면 됩니다. 메뉴 목록은 화면 진입 시 한 번만 읽어 캐시합니다.

**Q. 문서를 다른 카테고리로 옮기고 싶어요.**
A. 화면에는 이동 기능이 없습니다. 새 위치에 문서를 만들어 내용을 복사해 옮기거나, DB 담당자에게 `PLM_DOC_MENU.GROUP_ID` / `PARENT_ID` 변경을 요청하세요.

**Q. 순서를 바꾸고 싶어요.**
A. 정렬은 `PLM_DOC_MENU.SORT_NO` 기준이며 화면에서는 변경할 수 없습니다. 담당자에게 요청하세요.

**Q. 실수로 문서를 지웠어요.**
A. 본문은 `PLM_LLM_METADATA` 에 남아 있습니다. **지운 문서의 코드(예: `SPEC00012`)** 를 알려 주면 복구할 수 있습니다. 코드는 삭제 전 상단 API 카드 주소의 `type=` 값에서 확인할 수 있습니다.

## 15. 팀 운영 규칙 (요약)

1. **업무 문서는 반드시 "명세서" 영역에** 만든다. (`새 문서 작성` 버튼은 개인 메모용)
2. **카테고리는 각자 필요에 따라 직접 만든다.** 단, 비슷한 카테고리를 중복 생성하지 말고 기존 것이 있으면 그 아래 문서로 추가한다.
3. **API 주소는 만들지 말고 화면 상단 카드에서 복사해 쓴다.** (문서 코드는 서버가 자동 발급)
4. **작성자 이름을 반드시 입력**한다. 문서 상단 메타에 표시되어 문의 창구가 된다.
5. **한 문서 = 한 담당자.** 여러 명이 쓸 때는 사람별 하위 문서로 나눈다. (동시 저장 시 덮어쓰기)
6. **다른 사람의 문서 · 카테고리는 확인 없이 삭제하거나 이름을 바꾸지 않는다.**
7. 문서 끝에는 가급적 **변경 이력 표**를 남긴다.

| 테이블 스크립트 | `src/main/resources/sql/PLM_DOC_MENU.sql` |

### 데이터 저장 구조

```
PLM_DOC_MENU  (사이드바 메뉴 구조)
  ID          ← 메뉴 코드. SPEC00001 … 자동 발급
  MENU_TYPE   ← 'GROUP'(카테고리) | 'SPEC'(문서)
  NAME, ICON, COLOR
  GROUP_ID    ← 소속 카테고리
  PARENT_ID   ← 상위 문서 (없으면 최상위, 단계 제한 없음)
  SORT_NO     ← 정렬 순서
  READ_URL    ← 조회 API (NULL 이면 목업)
  SAVE_URL    ← 저장 API (NULL 이면 읽기 전용)
        │
        │  ID == CATEGORY 로 1:1 연결
        ▼
PLM_LLM_METADATA  (마크다운 본문)
  CATEGORY, CONTENT
```

- 문서를 만들면 `READ_URL` / `SAVE_URL` 이 규칙에 따라 자동 생성되고, 본문 행(`ensureContentRow`)도 미리 만들어 둡니다.
- 메뉴 API 호출이 실패하면 `api.js` 의 `SPEC_GROUPS` / `DB_SPEC_TYPES` 하드코딩 값으로 자동 대체되어 화면은 계속 동작합니다(읽기 참고용).
