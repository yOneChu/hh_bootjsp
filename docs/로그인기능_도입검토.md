# 로그인 기능 도입 검토

> 작성일: 2026-11-22
> 상태: 검토 완료, 구현 전 (결정 사항 확정 후 구현 요청 예정)

## 1. 배경

- 현재 애플리케이션(hh_bootjsp, Spring Boot 3.4.1, 포트 8070)에는 로그인 기능이 없어 누구나 접속해서 사용할 수 있다.
- 이 애플리케이션 **자체 로그인** 기능을 추가하려고 한다.
- 참고: `BomManageController`(`/cop/bom/login`)의 로그인은 **타 시스템(PLM)** 로그인이며, 이번 작업과는 별개다.

## 2. 결론

**수정량은 많지 않다.**

- 기존 컨트롤러 약 40개와 화면(Thymeleaf/JSP) 약 150개는 **수정하지 않는다.**
- Spring `HandlerInterceptor` 하나가 모든 요청 앞에서 세션을 검사하므로, 신규 파일 4개를 추가하고 기존 파일 2곳만 수정하면 된다.
- Spring Security 전체를 도입하지 않고 **세션 + 인터셉터 방식**을 권장한다.
  - Security를 도입하면 설정이 많고, CSRF 때문에 기존 POST/AJAX 요청(`fetch` 99곳, `$.ajax` 82곳)이 막히는 문제가 생긴다.
  - 나중에 권한 체계가 복잡해지면 그때 Security로 옮긴다.

## 3. 수정 범위

| 구분 | 파일 | 내용 |
|---|---|---|
| 신규 | `config/WebConfig.java` | 인터셉터 등록. 정적 리소스(`/resources/**`, css, js, 이미지), `/login`, 외부 API 경로는 검사에서 제외 |
| 신규 | `interceptor/LoginInterceptor.java` | 세션에 로그인 정보가 없으면 페이지 요청은 `/login`으로 리다이렉트, AJAX 요청은 **401** 응답 |
| 신규 | `controller/LoginController.java` | `GET /login` 화면, `POST /login` 처리, `POST /logout` |
| 신규 | `templates/thymeleaf/login.html` | 로그인 화면 |
| 수정 | `templates/thymeleaf/fragments/sidebar.html` | 사용자 이름, 로그아웃 버튼 표시 (이 사이드바를 쓰는 화면 전체에 적용) |
| 수정 | 공통 JS 1곳 | AJAX가 401을 받으면 로그인 화면으로 이동 (세션 만료 대응) |
| 추가 | `pom.xml` | `spring-security-crypto` 의존성 (BCrypt 해시용, Security 전체 아님) |
| 추가 | DB | 사용자 테이블 (`APP_USER`) |

### 로그인 흐름

```
요청 → LoginInterceptor
        ├─ 세션에 LOGIN_USER 있음 → 컨트롤러 진행
        └─ 없음
             ├─ AJAX 요청 (X-Requested-With / Accept: application/json) → 401
             └─ 일반 페이지 요청 → /login?redirect=원래URL 로 리다이렉트

POST /login → APP_USER 조회 → BCrypt 비밀번호 검증
             → 성공: 세션에 UserDTO(사번, 이름, 권한) 저장 → 원래 URL로 이동
             → 실패: 오류 메시지와 함께 로그인 화면
```

## 4. 사용자 테이블 (안)

```sql
CREATE TABLE APP_USER (
    SABUN      VARCHAR(20)  PRIMARY KEY,  -- 사번 (로그인 ID)
    NAME       NVARCHAR(50),
    PASSWORD   VARCHAR(100),              -- BCrypt 해시로 저장 (평문 저장 금지)
    ROLE       VARCHAR(20),               -- ADMIN / USER
    USE_YN     CHAR(1) DEFAULT 'Y',
    CREATED_AT DATETIME DEFAULT GETDATE()
);
```

- 비밀번호는 `BCryptPasswordEncoder`로 해시해서 저장한다.
- 기존 `UserDTO`(OID, 사번, 이름, 이메일)를 세션에 담는 객체로 확장해서 쓴다.
- `util/user/UserCommonUtil.getUserInfo()`가 PLM 사용자 마스터(`FUSER$SF`)를 조회하고 있으므로, 사용자를 등록할 때 사번과 이름을 가져오는 데 활용할 수 있다.

## 5. 구현 전 결정 사항

- [ ] **사용자 테이블**: 위 `APP_USER` 구조로 새로 만들어도 되는지, 테이블명이나 DB(현재 `PLMPRDIF`)를 따로 지정해야 하는지
- [ ] **`/api/**` 경로를 외부 시스템이 호출하는지**: `APIController`, `ShipAPIController`, `ChatApiController` 등을 배치나 타 서버가 호출한다면 로그인 검사에서 제외하거나 API 키 방식으로 따로 보호해야 한다. 그냥 막으면 연동이 끊긴다.
- [ ] **사용자 등록 방식**: 관리자가 등록(DB INSERT 또는 관리 화면)할지, 사용자가 직접 가입할지. 사내 도구라면 관리자 등록을 권장한다.
- [ ] **초기 비밀번호 정책**: 초기 비밀번호를 어떻게 부여할지, 첫 로그인 때 변경을 강제할지
- [ ] **권한 구분**: 1차에는 로그인 여부만 확인하고, 필요하면 `ROLE` 컬럼으로 메뉴 접근을 나눈다.
- [ ] **세션 타임아웃**: 기본값은 30분이다. 변경하려면 `server.servlet.session.timeout`을 설정한다.

## 6. 참고: URL 구조 (인터셉터 제외 대상 검토용)

컨트롤러의 `@RequestMapping` 접두어:

```
/api, /api/chat, /api/db, /api/docmenu
/cop/bom, /cycle, /dashboard, /eco, /excel, /jqpr, /mlb
/pidTest, /simulate, /simulateup, /simulateup/blockQtyCompare
/simulateup/specOverride, /simulplay, /track
```

이 외에 접두어 없이 메서드 단위로 매핑된 컨트롤러도 있다 (`HomeController`, `ViewController` 등).

## 7. 구현 요청 방법

결정 사항(5장)을 정한 뒤 이 문서를 첨부해서 요청한다. 예:

> `docs/로그인기능_도입검토.md` 기준으로 로그인 기능 구현해줘.
> 사용자 테이블은 APP_USER 그대로, /api/** 는 외부 호출이 있으니 제외, 사용자는 관리자가 등록.
